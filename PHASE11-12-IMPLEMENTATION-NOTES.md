# Phase 11 + 12 Implementation Notes (2026-08-29)

This pass implements Phase 11 (SaaS foundation & multi-outlet architecture) and
Phase 12 (Authentication, RBAC & authorization hardening) from
`RsSmart_Production_SaaS_Roadmap.md` against the Phase 10 codebase. See that
file's Phase 11/12 sections for the full writeup; this is a quick pointer to
what changed on disk.

## Before you do anything else

```bash
cd backend
npm install
npx prisma generate
```

**No live PostgreSQL or the Prisma engine binary was reachable from the build
sandbox** (`binaries.prisma.sh` isn't network-reachable there), so:
- `prisma/schema.prisma` was hand-edited and hand-checked field-by-field
  against every service that reads/writes it, but never run through
  `prisma validate`/`prisma generate` for real.
- The migration at
  `backend/prisma/migrations/20260829120000_multi_outlet_and_rbac/migration.sql`
  was hand-written (not generated by `prisma migrate dev`), following the
  same safe nullable-then-backfill-then-NOT-NULL pattern Prisma itself would
  use.

**Run `npx prisma generate` and `npx prisma migrate deploy` (or `migrate dev`
locally) against a real database, and read through the migration file, before
trusting this in anything beyond a dev/staging environment.** The migration
already has a checklist of manual post-migration steps at the bottom of the
file (deciding which existing tenants need their single default outlet split
into real physical outlets, etc).

## What changed

**Schema** (`backend/prisma/schema.prisma`):
- New `Outlet`, `UserOutlet` models, `OutletStatus` enum
- New `Role.scopeAllOutlets`, `User.tokenVersion`
- `outletId` added to `Inventory`, `StockMovement`, `Order`, `PosSession`,
  `PosCashMovement`; `Inventory`'s unique key changed to include `outletId`
  (stock is now tracked independently per outlet)

**New code:**
- `backend/src/common/permissions/` — permission catalog + default role presets
- `backend/src/common/decorators/public.decorator.ts`,
  `permissions.decorator.ts`, `outlet.decorator.ts`
- `backend/src/common/guards/jwt-auth.guard.ts`, `permissions.guard.ts`,
  `outlet.guard.ts` (new); `roles.guard.ts` fixed and now actually registered
- `backend/src/outlets/` — full CRUD + user-assignment module

**Changed code:**
- `backend/src/app.module.ts` — global guards wired in
- `backend/src/auth/*` — `registerCompany`/`inviteUser` split, fixed
  `JwtStrategy` (fresh roles/permissions, session revocation)
- `backend/src/users/*` — invite, disable/enable (now actually revokes
  sessions), role reassignment
- `backend/src/inventory/*`, `backend/src/pos-sessions/*`,
  `backend/src/pos-transactions/*`, `backend/src/orders/*` — outlet scoping
- `backend/src/health/health.controller.ts`,
  `backend/src/whatsapp/whatsapp.controller.ts` — marked `@Public()` (needed
  once `JwtAuthGuard` became global, or these would have started requiring a
  JWT and broken health checks / the Meta webhook)

**Tests** (all passing; run with `npm test` from `backend/`):
- `common/guards/outlet.guard.spec.ts`, `common/guards/rbac.guard.spec.ts`
- `outlets/outlets.service.spec.ts`, `inventory/inventory.service.spec.ts`
- `auth/strategies/jwt.strategy.spec.ts`, `users/users.service.spec.ts`
- `auth/auth.service.spec.ts` (rewritten for the new service shape)

Two pre-existing test files (`push/push.service.spec.ts`,
`health/health.controller.spec.ts`) fail in this sandbox on `ioredis` /
`firebase-admin` module-resolution errors unrelated to this change — worth a
quick look in your own environment, but nothing here touched that code.

## Not done in this pass (intentionally, see roadmap for detail)

- Cross-outlet stock transfers (only within-outlet warehouse transfers work)
- Migrating the ~13 pre-existing `@Roles(...)` call sites to the new
  permission system (they now actually get enforced for the first time,
  which is a real fix, but weren't rewritten)
- Dependency/vulnerability scanning, third-party pentest
- Everything in Phases 13+ (subscriptions, billing, onboarding UI, etc.)
